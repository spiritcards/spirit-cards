# 对战总览

**BATTLE v2** 是一种**托管式押注决斗**：双方各押**一张卡 + 等额 ETH**，赢家拿走奖池（减抽水），
输家失去卡的**3 条命中的 1 条**。战斗在**链上确定性结算**，但结果更接近**随机博弈**，而不是
「谁数值高谁必胜」。 `[proven]`

> [!WARNING]
> 对战是**零和**（再加抽水）的押注机制：你可能赢，也可能**输掉钱和卡**。不要用你输不起的
> 钱玩游戏。见 [法律声明](../project/legal-disclaimer.md)。

---

## 为什么值得单独一大章

战斗是这款游戏**最复杂的机制**，也是最能体现「策略 + 运气」的地方。它由四层因素叠加决定：

1. **数值**（HP / ATK / DEF）
2. **元素**（石头剪刀布，±20%）
3. **技能**（6 种特殊效果）
4. **每场攻击浮动**（±40%，来自区块随机数）

把四者叠加后，结果就变得**不是定局**——这正是设计意图。下面各页逐一拆解。

## 决斗一览

1. **创建。** 玩家 A 押上自己的卡 + 一笔 ETH（`createDuel(cardA, stake)`）→ 生成一个
   **公开决斗**。 `[proven]`
2. **接受。** 玩家 B 押上自己的卡 + **等额** ETH（`acceptDuel(id, cardB)`）→ 战斗**立即结算**。 `[proven]`
3. **取消。** 创建者可取消自己的公开决斗（`cancelDuel(id)`）→ 卡与押注退回。 `[proven]`
4. **不能自战。** 不能接受自己的决斗（A ≠ B）。 `[proven]`

- 押注须 **> 0**，双方押注**相同**。奖池 `pot = stake × 2`。 `[proven]`
- **赢家**拿走 `pot − 抽水`；**输家**失去 1 条命并失去押注。 `[proven]`
- **质押中的卡也能参战**（在金库中被锁定，质押者继续分红，无需授权）。 `[proven]`

→ 详见 [对战机制](overview.md) 与 [生命 · 押注 · 抽水](lives-stakes-and-rake.md)。

## 决定胜负的因素（速览）

| 因素 | 效果 | 参数 |
|---|---|---|
| 元素克制 | 伤害 **±20%** | `typeAdvBps = 2000` |
| 每次攻击浮动 | 伤害 **×[0.6, 1.4]** | `atkVarianceBps = 4000` |
| 技能 | 暴击/护盾/穿透/精准/坚韧 | 种子决定 |
| 数值 | ATK、DEF、HP | 种子决定 |

**平衡事实（重要）：** `[proven]`

- **数值接近**的两张卡 ≈ **五五开**（由浮动决定）。
- 一张**强约 25%** 的卡，胜率约 **72%**（较弱的一方仍有约 **28%** 的机会）。 `[assumed — 默认 ±40% 浮动下的估计]`
- **明显更强**的卡几乎必胜。

> [!NOTE]
> **公平性关键点：** 结果还取决于 **`acceptDuel` 执行区块的 `prevrandao`**，而接受方在**签名时
> 并不知道**它。所以「谁都不知道，直到入场」——没人能挑一个稳赢的时机。 `[proven]`

---

## 小结

- 决斗 = 托管押注：押卡 + 等额 ETH，赢家拿奖池减抽水，输家掉 1 条命。 `[proven]`
- 四层因素（数值 + 元素 + 技能 + 浮动）叠加 → **不是定局**。 `[proven]`
- 随机源是执行区块的 `prevrandao`，接受方签名时未知 → 无法预选稳赢时机。 `[proven]`
